# 数据核验说明

## 核验目标

对比大模型从网页截图中识别的字段值与任务二 JSON 中的参考值，评估模型在真实网页截图场景下的识别准确率。

## 数据来源

- **参考值**：任务二 `02_api_http/output/land_transactions.json`（CSS Selector / API 方案抓取）
- **识别值**：本项目通过 Playwright 截图 + Kimi K2.6 多模态模型识别

## 选择逻辑

从任务二 JSON 前 100 条中，按原有顺序每 10 条为 1 页，从每页选择第一条"已成交"记录，共 10 条。

选择"已成交"记录是因为：
- 已成交记录包含完整字段（成交时间、竞得人、成交地价等）
- 不成交记录缺少成交时间、竞得人、成交价格，不具代表性

## 比较方法

### 规范化处理

1. 去除首尾空白
2. 去除数字中的逗号分隔符（如 `15,746` → `15746`）
3. 转小写

### 匹配规则

- **完全匹配**：规范化后完全一致
- **数值近似**：面积、价格字段提取数字部分，允许 `math.isclose(rel_tol=1e-3, abs_tol=0.01)` 的浮点舍入差异
- **不匹配**：规范化后不一致

## 差异分类

### 普通识别差异

模型无法识别或识别值与参考值确实不一致的情况：
- 字段值为空或"待核验"
- 模型识别值规范化后与参考值不同
- 属于真正的 OCR 识别错误或信息缺失

### 字段口径差异（仅针对 `land_usage`）

API 中的 `land_usage` 是**土地用途分类**，由后端系统按固定类别编码；
截图中的 `land_usage` 是**土地实际用途**，由详情页展示的具体文字描述。

两者可能同时正确但文本不同。例如：
- API 返回："商服用地"
- 详情页显示："商业用地（零售商业用地、餐饮用地、旅馆用地），兼容娱乐用地"

这种情况：
- **不直接判定为 OCR 识别错误**
- 标记为 **"字段口径不同，需人工核验"**
- 单独记录到 `semantic_difference_fields`，不混入 `mismatch_fields`

## 人工核验建议

以下情况需要人工核验：
1. `parse_status = "parse_error"` — 模型输出格式无效
2. `verification_status = "needs_review"` 且存在 `mismatch_fields` — 有普通识别差异
3. `verification_status = "needs_review"` 且仅存在 `semantic_difference_fields` — 字段口径差异，需理解 API 分类与实际用途的对应关系
4. 模型标注了 `uncertain_fields` 的记录
5. 截图质量不佳（模糊、截断等）
